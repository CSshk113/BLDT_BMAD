# Final Adversarial Divergence Review — R2

## Verdict

**REVISE/FAIL**

This gate does not pass. Two independent implementations can comply with the prose while diverging in persisted identity, authorization, lifecycle, retry behavior, citation validity, question selection, interview verification, decision provenance, and API behavior.

Independent readings used for the check:

- **Implementation A:** strict state-machine implementation; preview artifacts are allowed before approval, every attempt is append-only, composite provenance is enforced in storage, and only LEAD selects questions or records interview/decision outcomes.
- **Implementation B:** minimal service implementation; upload requires approval, retries mutate a run row, “latest” is selected by timestamp, service code—not schema—checks relationships, and any handoff-accessible reviewer may select questions.

## Critical/high findings

1. **[Critical | phase-blocker] Preview eligibility is contradictory.** PRD §5/UF-1 and FR-004 allow exploratory work before approval (`prd.md:61-67`, `prd.md:75-85`), while the spine’s upload contract requires an approved version and its pipeline contract says approved criteria are the MVP basis (`ARCHITECTURE-SPINE.md:132-139`, `ARCHITECTURE-SPINE.md:215-233`). A can create `preview_mode` mappings; B rejects the same upload. **Guard:** define the preview state machine and explicitly state which artifacts may be produced pre-approval, how they are marked, and which reads/writes are blocked.

2. **[Critical | phase-blocker] F1 has no complete creation/calibration API contract.** The sequence uses `POST /api/criteria/calibrate` and then approval (`ARCHITECTURE-SPINE.md:284-292`), but Core API Contracts define only review, conflict, and approve endpoints, with no criteria-version creation, sample registration, or calibration request/response schema (`ARCHITECTURE-SPINE.md:215-226`). A and B will expose incompatible F1 setup flows.

3. **[Critical | phase-blocker] The PDF viewer has no defined authenticated retrieval contract.** The browser is forbidden from direct file-store access (`ARCHITECTURE-SPINE.md:159-168`), the UI requires PDF rendering (`PRESENTATION-SYSTEM-DESIGN.md:23-33`), and the handoff response vaguely says it returns “original text” without a PDF stream/download endpoint or authorization/data shape (`ARCHITECTURE-SPINE.md:228-230`, `ARCHITECTURE-SPINE.md:395-405`). A proxies an authenticated PDF; B exposes a file URL or embeds extracted text, producing different demo and security behavior. **Guard:** specify a FastAPI PDF retrieval endpoint, range/stream behavior, authorization scope, content type, and non-path response.

4. **[Critical | phase-blocker] The official output-set identity is required but not modeled end-to-end.** AD-10 requires `(application_id, criteria_version_id, source_processing_run_id, normalized_markdown_hash)` on every output (`ARCHITECTURE-SPINE.md:170-177`), but `HANDOFF_CARD`, `INTERVIEW_QUESTION_CANDIDATE`, `INTERVIEW_VERIFICATION`, and `DECISION_RECORD` omit the normalized hash, and several omit the processing-run identity (`ARCHITECTURE-SPINE.md:490-562`). A derives provenance through the run; B uses application/version plus “latest.” Those implementations can assemble different official cards from the same IDs. **Guard:** add the complete provenance key or define one canonical immutable parent object and require every child to reference it.

5. **[Critical | phase-blocker] Cross-parent provenance is an application/service promise, not a relational constraint.** AD-2 and AD-10 require application, criteria version, and processing run to agree (`ARCHITECTURE-SPINE.md:101-107`, `ARCHITECTURE-SPINE.md:170-176`), while the ERD shows only independent scalar FKs for mappings/citations/reviews/conflicts (`ARCHITECTURE-SPINE.md:430-488`). A enforces composite parent checks; B accepts a valid citation or run from another application/version. **Guard:** define composite foreign keys/checks or one canonical provenance FK, plus uniqueness rules for current mappings.

6. **[Critical | phase-blocker] Calibration approval completeness is not enforceable.** Approval requires every sample to have independent HR and TECH review and all conflicts resolved (`ARCHITECTURE-SPINE.md:92-100`), but the ERD has no review uniqueness/completeness constraint per sample, criterion, role, or version (`ARCHITECTURE-SPINE.md:380-386`, `ARCHITECTURE-SPINE.md:454-488`). A counts distinct roles; B counts rows, so duplicates can satisfy the gate. **Guard:** specify the calibration sample universe, required review cardinality, uniqueness key, and atomic approval query/transaction.

7. **[High | phase-blocker] Question authorization is internally inconsistent.** The question contract permits any role with current-handoff access (`ARCHITECTURE-SPINE.md:201-213`), while the role contract gives question selection to LEAD (`ARCHITECTURE-SPINE.md:233-235`); PRD FR-021 says “reviewer” and the presentation assigns the action to the 현업 리더 (`prd.md:121-127`, `PRESENTATION-SYSTEM-DESIGN.md:113-130`). A allows TECH/HR selection; B allows only LEAD. **Guard:** assign an exact role and ownership rule separately for generate, edit, delete, select, verify, and decide, and put it in each endpoint contract.

8. **[Critical | phase-blocker] Idempotency scope and attempt history are underspecified.** Upload/retry/external-call idempotency is required (`ARCHITECTURE-SPINE.md:144-149`, `ARCHITECTURE-SPINE.md:219-233`), but the schema has only one `idempotency_key`, `attempt_no`, and `provider_request_id` per `PROCESSING_RUN` and no uniqueness/scope or per-attempt table (`ARCHITECTURE-SPINE.md:408-428`). A creates immutable attempt rows; B overwrites the same row. Same keys can therefore return different applications or lose provider audit history. **Guard:** define key scope `(actor/workspace, endpoint, payload fingerprint, criteria version)`, unique constraints, replay response, and immutable per-attempt records.

9. **[High | phase-blocker] Processing transitions do not protect against stale workers.** The application and run enums are listed, but no legal transition table, compare-and-set rule, cancellation/supersession state, or stale-worker rule is defined (`ARCHITECTURE-SPINE.md:132-149`, `ARCHITECTURE-SPINE.md:395-428`). A lets the newest successful run win; B lets a late failed worker overwrite `COMPLETED`. **Guard:** define transition preconditions and atomic ownership of `current_processing_run_id`, including concurrent retry and worker restart behavior.

10. **[Critical | phase-blocker] Exact-citation semantics are not reproducible.** “Exact substring” is required (`ARCHITECTURE-SPINE.md:101-107`), but the artifacts do not define Unicode normalization, newline/whitespace normalization, offset units, inclusive/exclusive end offsets, hash scope, or whether offsets address normalized bytes/code points (`ARCHITECTURE-SPINE.md:430-442`). A and B can both claim exact matching while highlighting different text. **Guard:** specify the canonical normalization algorithm, offset coordinate system, hash input, and validation test vectors.

11. **[High | phase-blocker] Markdown block/location identity has no canonical entity or lifecycle.** The ERD references `DOCUMENT_PAGE` but never defines it, and `markdown_block_id` is an unconstrained string (`ARCHITECTURE-SPINE.md:331-367`, `ARCHITECTURE-SPINE.md:430-442`). The location resolver only says it connects blocks/pages/context (`ARCHITECTURE-SPINE.md:250-260`). A uses parser-native IDs; B renumbers blocks during normalization, breaking citation replay and split-view sync. **Guard:** define stored document blocks/pages, stable ID generation, and the relationship between raw Markdown, normalized Markdown, and offsets.

12. **[High | phase-blocker] Question generation can duplicate or mix revisions.** `generation_key` is prescribed, but no uniqueness constraint, generation idempotency response, source processing-run/hash, or current-revision selector is defined (`ARCHITECTURE-SPINE.md:123-130`, `ARCHITECTURE-SPINE.md:170-177`, `ARCHITECTURE-SPINE.md:201-213`, `ARCHITECTURE-SPINE.md:500-534`). The list contract returns all non-deleted candidates, not only the active source revision (`ARCHITECTURE-SPINE.md:205-213`). A replaces/replays a generation; B appends duplicates and displays old candidates with new ones. **Guard:** make generation uniqueness and replay behavior explicit and require GET/hand-off assembly to select one source revision.

13. **[High | phase-blocker] Candidate grounding rules are not enforced by the model/API contract.** A candidate must have a criterion or structured concern, and fact-verification questions must have citation(s) (`ARCHITECTURE-SPINE.md:123-130`), but the ERD/API do not define conditional constraints or a validation error for missing evidence (`ARCHITECTURE-SPINE.md:500-525`). A rejects invalid candidates; B persists them and exposes them in the handoff. **Guard:** specify conditional validation, same-handoff/same-provenance checks, and the exact error envelope for invalid generation/edit requests.

14. **[Critical | phase-blocker] Interview verification identity and revision semantics are incomplete.** The rule allows verification only for selected questions and separates hypothesis from finding (`ARCHITECTURE-SPINE.md:151-157`), but `INTERVIEW_VERIFICATION` has independent handoff/question FKs, no question-revision FK, no processing/hash provenance, and no uniqueness/latest rule for `revision_no` (`ARCHITECTURE-SPINE.md:536-549`). A records the selected question revision and rejects cross-handoff links; B accepts any valid question ID and chooses latest by timestamp. **Guard:** enforce same handoff/card revision and selected status transactionally, reference the exact question revision/hypothesis snapshot, and define append-only revision ordering and replay behavior.

15. **[Critical | phase-blocker] Decision API and provenance gates are insufficient.** The endpoint is keyed only by application (`ARCHITECTURE-SPINE.md:228-231`), while the record also needs a handoff, criteria version, source revision, and evidence citations (`ARCHITECTURE-SPINE.md:551-567`). No request field/selection rule identifies the handoff, no citation requirement is stated, no uniqueness/latest decision rule exists, and no gate says whether all selected questions must be terminal before deciding (`ARCHITECTURE-SPINE.md:151-157`). A decides against the current handoff with required citations; B accepts an application-level decision with zero citations. **Guard:** bind the endpoint to `handoff_id` or require an explicit immutable handoff identity, define evidence minimums and verification preconditions, and specify append-only decision revision semantics.

16. **[High | deferred unless diagram is contractual] Service topology diverges between the spine and presentation summary.** The spine includes an Evidence Matcher and Review/Handoff services between the API and pipeline (`ARCHITECTURE-SPINE.md:56-85`), while the presentation routes the API directly to the pipeline and omits Evidence Matcher/Decision ownership (`PRESENTATION-SYSTEM-DESIGN.md:36-75`). A follows the spine; B follows the presentation. **Guard:** label the presentation diagram illustrative or align its service/data-ownership boundaries before implementation. This is documentation-only if the spine is explicitly authoritative; otherwise it becomes a phase-blocker.

17. **[High | phase-blocker] Error contract is not actually executable.** The spine combines a custom success/error wrapper with “RFC 7807 compatible” errors but does not define HTTP status mapping, conflict/authorization/not-found/idempotency errors, or correlation-ID propagation (`ARCHITECTURE-SPINE.md:189-197`, `ARCHITECTURE-SPINE.md:215-235`). A returns `409` with a wrapped error; B returns `422` or native problem details, so frontend behavior diverges. **Guard:** provide a per-endpoint status/error matrix and one canonical envelope, including replay responses and authorization failures.

## Blocker disposition

Findings **1–15 and 17 are genuine phase-blockers** for the next implementation phase because they permit incompatible state, identity, authorization, or API behavior. Finding **16 is deferred only if the presentation diagram is explicitly non-contractual and the spine is declared authoritative**. No other deferred item (D-01–D-07) resolves these blockers; those remain ordinary demo-scope deferrals (`ARCHITECTURE-SPINE.md:610-622`, `prd.md:274-286`).

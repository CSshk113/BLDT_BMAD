- (decision) 공식 UX 입력은 최종 PRD와 addendum, Architecture Spine, Presentation System Design, 그리고 사용자 지정 참고 사이트 https://codepresso.io/ 이다.
- (decision) 시각 방향은 Code.Presso와 유사한 신뢰감 있는 B2B 기술 제품 분위기다. Pretendard 계열 산세리프, 선명한 블루 #1A61EA 및 #356DDE, 옅은 블루 표면 #F6FAFF 및 #F7F9FC, 짙은 네이비, 절제된 6–12px 라운딩, 데이터 중심 카드 구성을 참고한다.
- (assumption) 별도 작업 모드 지정이 없어 5일 MVP 일정에 맞춘 Fast path로 진행하며, 사용자에게 확인받지 않은 결정은 문서에서 ASSUMPTION으로 표시한다.
- (assumption) Architecture의 Next.js UI와 90초 데모 계약을 근거로 데스크톱 우선 반응형 웹을 기본 폼팩터로 삼고, 모바일은 조회 및 단순 조작을 보조하는 범위로 둔다.
- (event) Code.Presso 공개 홈페이지와 hiring 페이지, 공개 CSS 및 제품 화면 이미지를 2026-08-27에 참고 조사했다. 공개 사이트의 구성과 토큰을 참고하되 자산이나 레이아웃을 복제하지 않는다.
- (assumption) 채용 판단을 다루므로 접근성, 공정성·비차별 언어, 근거 추적성, 상태 투명성, 고밀도 정보의 가독성을 핵심 UX concern으로 취급한다.
- (decision) 소스가 정의한 주요 인물과 여정은 민지의 UF-1 기준 합의와 검토 시작, 준호의 UF-2 근거 기반 지원서 검토, 서연의 UF-3 현업 핸드오프와 인터뷰 검증이다.
- (decision) IA는 기준 교정·승인, 지원서 처리 목록, 근거 검토 스플릿 뷰, 이견 비교, 핸드오프 카드, 질문 후보 편집, 면접 검증·최종 결정, 감사 기록 표면을 모두 포함해야 한다.
- (decision) 공식 UX 순서는 calibration → review → handoff이며, 동일 criteria_version_id 맥락과 승인 게이트를 전 구간에서 유지한다.
- (assumption) 역할 식별 방식이 미정이므로 MVP 데모에서는 헤더에 현재 역할 HR·TECH·LEAD를 명시하고 데모 전환기를 제공하되, 운영 인증·SSO로 오해되지 않게 데모 전용임을 표시한다.
- (assumption) 문서 간 질문 편집 권한이 모호하므로 MVP UX에서는 LEAD가 질문 후보 수정·삭제·선택을 수행하고 HR·TECH는 연결 근거를 열람한다. 구현 전에 권한 계약을 확정한다.
- (assumption) 핸드오프 생성 주체가 모호하므로 MVP UX에서는 TECH 검토 완료 후 생성 조건을 충족한 지원서에 대해 LEAD가 공식 핸드오프 생성을 확정한다. 구현 전에 API 권한 계약을 확정한다.
- (assumption) 90초 데모는 사전 처리된 합성 지원서에서 시작하고 업로드·재처리는 별도 관리 표면으로 남긴다. 실제 PDF 업로드 기능 요구는 유지한다.
- (assumption) MVP는 라이트 모드만 제공하고 WCAG 2.2 AA, 키보드 전 조작, 상태의 텍스트·아이콘 중복 표기, PDF 텍스트 fallback을 접근성 바닥으로 둔다.
- (assumption) 정확한 질문 후보 수, 발표 데이터 수량, 좌표 하이라이트 지원 범위, 충돌 해결 API, 재시도 API는 소스의 deferred 또는 계약 공백으로 유지하며 UX가 임의로 확정하지 않는다.
- (event) DESIGN.md와 EXPERIENCE.md 초안 작성 및 YAML, canonical section order, 토큰 참조, 양 문서 컴포넌트 명칭 일치를 확인했다.

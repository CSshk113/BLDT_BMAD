- (assumption) Architecture의 Next.js UI와 90초 데모 계약을 근거로 데스크톱 우선 반응형 웹을 기본 폼팩터로 삼고, 모바일은 조회 및 단순 조작을 보조하는 범위로 둔다.

- (decision) 소스가 정의한 주요 인물과 여정은 민지의 UF-1 기준 합의와 검토 시작, 준호의 UF-2 근거 기반 지원서 검토, 서연의 UF-3 현업 핸드오프와 인터뷰 검증이다.

- (decision) 공식 UX 순서는 calibration → review → handoff이며, 동일 criteria_version_id 맥락과 승인 게이트를 전 구간에서 유지한다.
- (assumption) 역할 식별 방식이 미정이므로 MVP 데모에서는 헤더에 현재 역할 HR·TECH·LEAD를 명시하고 데모 전환기를 제공하되, 운영 인증·SSO로 오해되지 않게 데모 전용임을 표시한다.
- (assumption) 문서 간 질문 편집 권한이 모호하므로 MVP UX에서는 LEAD가 질문 후보 수정·삭제·선택을 수행하고 HR·TECH는 연결 근거를 열람한다. 구현 전에 권한 계약을 확정한다.
- (assumption) 핸드오프 생성 주체가 모호하므로 MVP UX에서는 TECH 검토 완료 후 생성 조건을 충족한 지원서에 대해 LEAD가 공식 핸드오프 생성을 확정한다. 구현 전에 API 권한 계약을 확정한다.
- (assumption) 90초 데모는 사전 처리된 합성 지원서에서 시작하고 업로드·재처리는 별도 관리 표면으로 남긴다. 실제 PDF 업로드 기능 요구는 유지한다.

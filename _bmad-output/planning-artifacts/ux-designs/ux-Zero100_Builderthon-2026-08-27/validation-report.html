2. Token completeness

thin

25개 토큰 참조는 모두 해석되고 모든 색상에 hex가 있으나, 입력 경계 대비와 상태 배지의 전경/배경 계약이 충분하지 않다.

high

입력 경계가 비텍스트 UI 대비 기준에 미달

DESIGN.md colors.border-strong / field-control
#BEC3CF와 #FFFFFF의 계산 대비는 약 1.77:1로 문서가 약속한 3:1 바닥과 충돌한다.
Fix: 3:1 이상인 입력 전용 border 토큰이나 동등한 형태·톤 신호를 계약한다.
medium

상태 배지의 전경/배경 토큰과 대비 근거 부재

DESIGN.md status-badge, §Colors
성공·주의·실패의 정확한 토큰 쌍과 load-bearing 대비가 정의되지 않았다.
Fix: 상태별 foreground/background 참조와 검증된 대비를 기록한다.

3. Component coverage

adequate

제품 고유 컴포넌트 18개가 YAML, DESIGN 시각 규칙, EXPERIENCE 행동 규칙에 정확히 대응한다.

medium

공통 UI 프리미티브의 상속 근거 부재

DESIGN.md §Elevation; EXPERIENCE.md §Interaction Primitives
skeleton, 탭, 팝오버, 확인 UI, 오류 요약, live region을 사용하지만 계약 또는 상속 UI 시스템이 없다.
Fix: 접근 가능한 primitive 시스템을 명시하거나 핵심 프리미티브를 양쪽 spine에 추가한다.

4. State coverage

thin

일곱 IA 표면의 주요 오류와 차단 상태는 있으나, 아키텍처 열거형과 후반 표면의 정상·예외 상태 계약이 빠져 있다.

high

아키텍처 상태 열거형이 화면 상태 계약에서 누락

ARCHITECTURE-SPINE.md §핵심 상태; EXPERIENCE.md §State Patterns
ARCHIVED, COMPLETED, RESOLVED, CANDIDATE/SELECTED/DELETED의 표시·행동·전이가 명시되지 않았다.
Fix: 각 열거형을 상태 표의 별도 행으로 만들고 표면, 문구, 행동, 읽기 전용 여부, 다음 전이를 기록한다.
medium

핸드오프·최종 결정·감사 기록의 정상/예외 상태 부족

EXPERIENCE.md §IA, §State Patterns
생성 중·완료, 이미 확정됨, 감사 기록 empty/filter-empty/load-error 등이 표면별로 정의되지 않았다.
Fix: 세 표면에 cold-load, empty, submitting, success/immutable, stale/conflict, recoverable error를 추가한다.

5. Visual reference coverage

adequate

시각 자산 파일은 0개여서 orphan은 없고 Code.Presso 방향은 source와 reconciliation 문서에서 구체화되어 있다.

시각 참조 충돌 시 spine 우선 규칙이 spine 밖에만 존재

reconcile-codepresso-reference.md
향후 mockup/import가 생기면 문서 우선순위를 spine에서 직접 찾을 수 없다.
Fix: 시각 참조를 처음 연결할 때 두 spine이 시각 자산보다 우선한다는 규칙을 한 번 명시한다.

6. Bloat & overspecification

strong

표와 짧은 규칙 중심이며 소스 설명을 반복하지 않는다. 추가 섹션과 픽셀 값은 downstream 결정과 구현 계약을 소유한다.

7. Inheritance discipline

thin

로컬 source, UF 이름, 제품 컴포넌트와 토큰 참조는 일치하지만 핵심 행위자 권한 계약이 소스와 UX 사이에서 충돌한다.

high

질문·핸드오프 권한 주체가 소스와 UX에서 충돌

Architecture AD-5/AD-9/Structural Seed; EXPERIENCE UF-3
질문 생성·수정·삭제·선택과 핸드오프 생성의 담당자가 TECH/LEAD 사이에서 확정되지 않았다.
Fix: 행동별 RACI/권한 행렬을 확정하고 Architecture와 EXPERIENCE를 함께 갱신한다.

8. Shape fit

strong

DESIGN의 정규 섹션 순서와 EXPERIENCE의 필수·조건부 섹션이 모두 적합하며, 추가 섹션도 제품 요구에 필요한 역할이 분명하다.

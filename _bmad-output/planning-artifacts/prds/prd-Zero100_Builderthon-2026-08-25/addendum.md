# PRD Addendum — 구현 결정과 환경 설정

이 문서는 PRD의 제품 요구사항을 구현할 때 필요한 기술 선택을 보존한다. 기술 선택이 바뀌면 PRD의 기능 의도와 인수 조건을 먼저 확인한 뒤 이 문서를 갱신한다.

## 입력 파이프라인

1. 사용자는 PDF 지원서를 입력한다.
2. 애플리케이션은 PDF를 LlamaParse로 변환한다.
3. LlamaParse가 반환한 Markdown을 기준 매핑과 인터뷰 질문 후보 생성의 정규화된 텍스트 입력으로 사용한다.
4. 원본 PDF와 변환 Markdown은 같은 지원서 ID로 연결한다.
5. Markdown에 페이지·헤딩·문단 정보가 있으면 근거 위치로 보존한다. 변환 결과로 위치를 안정적으로 확인할 수 없으면 스니펫·페이지·주변 문맥 fallback을 사용한다.

## AI 모델과 API 설정

- MVP와 베이스라인 모델: `gpt-5.6-luna`
- 실제 사용 전 프로젝트 계정에서 모델 ID 가용성을 확인하고, 사용 시점에 제공되는 정확한 API 모델 스냅샷을 고정한다. 가용하지 않은 모델로 조용히 대체하지 않는다.
- 모델 목록 확인 기준: [OpenAI 모델 목록](https://developers.openai.com/api/docs/models)
- API 키와 API base URL은 환경 변수로 분리한다. 예시는 다음과 같다.

```env
OPENAI_API_KEY=replace-me
OPENAI_BASE_URL=https://api.openai.com/v1
```

- 비밀값은 `.env` 파일에 저장하되 저장소에 커밋하지 않는다. 저장소에는 `.env.example`만 제공한다.
- 모델 공급자 또는 API endpoint를 바꾸는 경우에는 모델의 근거 추적성과 출력 스키마가 유지되는지 먼저 검증한다.
- 정확한 모델 변경은 별도의 제품 결정으로 취급하며, 단순한 API 키 교체와 구분한다.

## 베이스라인 재현 계약

- 비교 사례는 대표 지원서 5건으로 고정한다.
  - 명확한 충족
  - 부분 충족
  - 근거 부족
  - 검토자 의견 충돌
  - 인터뷰 질문 생성이 필요한 사례
- 각 사례를 3회 실행해 총 15회 결과를 확인한다.
- 모든 실행에 페이지 구분이 포함된 지원서 원문, 동일한 승인 기준, 동일한 두 검토자의 판단·사유를 입력한다.
- 프롬프트는 제품 내부 데이터 구조나 정답을 제공하지 않는 일반적인 “근거 기반 핸드오프와 인터뷰 질문 작성” 요청으로 구성한다. 정확한 실행 문자열을 저장한다.
- 다음 실행 메타데이터와 산출물을 저장한다.
  - 모델명·API 스냅샷
  - 프롬프트
  - API 파라미터
  - 원본 응답
  - 실행 시각
  - 요청 ID
- 비교 기준은 원문 인용 정확성, 페이지·위치 정확성, 근거 없는 추론 수, 확인 불가 처리, 검토자 이견 보존, 인터뷰 질문의 기준·근거 연결, 반복 실행 간 결과 일관성이다.

### PB-02 해결 절차 — Deferred

1. 위 다섯 유형을 대표하는 지원서 사례 5건을 준비한다. 이는 전체 발표용 데이터 세트를 확정하는 작업과 분리된 베이스라인 비교 표본이다.
2. 프로젝트 계정에서 `gpt-5.6-luna` 호출 가능 여부와 사용 가능한 정확한 API 스냅샷을 확인한다.
3. 페이지 구분 원문, 승인 기준, 두 검토자의 판단·사유를 고정하고, 제품 내부 구조나 정답을 포함하지 않은 일반 요청형 프롬프트를 고정한다.
4. 각 사례를 동일 조건으로 3회씩 실행해 총 15회의 원본 응답과 실행 메타데이터를 저장한다.
5. 일곱 가지 비교 기준으로 사례별 결과와 반복 실행 간 변동을 기록한다.
6. 대표적인 차이가 드러나는 한 사례를 골라 `DEL-003` 비교 화면을 만들고, 결과표와 원본 응답 저장 위치를 함께 보존한다.

PB-02는 현재 실행하지 않는다. 추후 `DEL-003` 제작을 시작할 때 모델 가용성 확인, 15회 실행, 메타데이터 저장, 비교 결과표, `DEL-003` 대표 화면이 모두 완료되면 해결된 것으로 본다.

## 발표용 클릭 범위 — 약 90초

| 순서 | 액션 | 시간 |
|---:|---|---:|
| 1 | 승인된 기준 버전 확인 | 10초 |
| 2 | 처리 상태 목록에서 대표 지원서 선택 | 10초 |
| 3 | 인용구 클릭 후 원문 위치 또는 대체 문맥 확인 | 25초 |
| 4 | 두 검토자의 의견 차이와 근거 확인 | 15초 |
| 5 | 핸드오프 카드 열기 | 10초 |
| 6 | 인터뷰 질문 후보 수정·삭제·선택 | 20초 |
| **합계** |  | **90초** |

클릭 범위 밖의 로딩·오류·베이스라인 비교 화면은 발표 시나리오에 필요할 때 별도 화면으로 준비하되, 대표 클릭 흐름을 방해하지 않는다.

## 기존 아키텍처와의 동기화 메모

아키텍처 문서는 PDF→LlamaParse→Markdown, `gpt-5.6-luna`, 발표용 데이터 수량 deferred, 90초 클릭 데모 흐름을 반영하도록 동기화했다. 아키텍처 spine의 별도 finalization은 이 PRD finalization의 범위에 포함하지 않는다.

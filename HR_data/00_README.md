# 코드프레소 채용 데이터 패키지

> 2026 에이전트 바이브코딩 해커톤 (싱가포르) · 문제 01 저지먼트 트랙 "코드프레소 채용"
> 참가팀 제공 데이터. 문의: 코드프레소 인사팀.

## 배경 (문제 설정과의 관계)

문제지의 설정 — ATS 없음 / 채용 담당 1명 / 공고당 대량 접수 / 상위 일부만 검토 / 판단 기록 소실 —
은 실제 운영 데이터를 기반으로 합니다. 이 패키지는 **B2B 영업 매니저 채용 사이클
(2026-03-03 ~ 07-08, 접수 178건, 최종 채용 1명)** 의 실데이터를 가명화해 제공합니다.

## 구성

| 폴더 | 내용 |
|---|---|
| `01_ledger/` | **지원 접수 원장 178건 CSV** — 전 접수분의 채널·지원일·판정·단계 결과. 이름은 `후보NNN` 치환(같은 사람의 재지원은 같은 토큰 — 중복지원 신호 보존) |
| `02_judgment/` | **판단 사례 요약표 15건** — HR 스크리닝 4분류부터 최종 채용까지 판정 유형별 실제 사례. 원장과 `후보NNN` 조인 |
| `03_resumes/` | **이력서 표본 20건** (DOCX+PDF) — 전형 구간별(A 스크리닝 탈락 6 / B 서류 탈락 8 / C 면접 탈락 3 / D 면접 통과 3). `표본매핑표.csv`로 원장과 조인 |
| `04_internal-docs/` | **내부 자료 5종** — ① 채용 프로세스 전체 구조 ② 지원자 DB 스키마·운영 ③ HR 스크리닝 판정 기준 ④ 공고 게시 가이드(+실제 JD) ⑤ 면접 설계 자료(질문 은행 포함) |

## 데이터 사전 (원장 CSV 컬럼)

`ID`(접수 일련) / `채용 채널` / `이름`(→후보NNN) / `지원일` / `포지션` / `현황` /
`HR`(스크리닝 불합격 여부 Yes=탈락) / `불합격 사유`(복수 가능) / `서류심사` / `1차면접` / `2차면접` / `최종결과`
— 필드·상태값 정의는 `04_internal-docs/03_스크리닝판정기준/notion_status_values.md` 가 정본입니다.

## 가명화 고지

- 지원자 실명 → `후보NNN`(원장 조인 키). 이력서 표본의 인명은 **전부 가상 이름**입니다.
- 재직사·고객사·학교는 가상 기업명 또는 동종 업계 실존 기업으로 치환·스왑되었습니다.
  이력서에 등장하는 기업명은 해당 인물의 실제 이력을 의미하지 않습니다.
- 연락처·이메일은 더미(`010-0000-0000` / `name@example.com`)입니다.
- 직원 → `담당자X`, 과거 사이클 후보 → `후보A~O`, 노션 ID → `{NOTION_ID}`.
